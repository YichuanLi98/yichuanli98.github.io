# 作品站编辑操作手册

本站的正式内容以 GitHub `master` 分支为唯一数据源，图形化编辑器地址为 `/admin/`。编辑器使用 Netlify Identity 和 Git Gateway，站点预览使用 Netlify Deploy Preview，正式站仍由 GitHub Pages 发布。

## 登录与权限

1. 打开 `https://<Netlify 站点域名>/admin/`。
2. 选择 GitHub 登录，使用 `YichuanLi98` 账号授权。
3. Netlify Identity 必须保持“仅邀请”，且只启用 GitHub 外部登录提供方。不要开启公开注册，不要在仓库中记录邀请邮箱、令牌或 OAuth 密钥。
4. 未收到邀请的访客可以查看网站和预览链接，但不能进入编辑器修改内容。

## 新建和预览草稿

1. 在“站点设置”中修改文案、导航、首屏作品、摄影/绘画作品顺序、页脚和联系方式；在“摄影作品”或“绘画作品”中管理单件作品。
2. 上传图片只使用 JPEG、PNG 或 WebP，单个文件不超过 15 MiB。每件作品必须填写作品名称和替代文字。
3. 点击“保存”只会建立草稿，不会修改 `master` 或正式站。状态可从“草稿”移到“审核中”，再进入“可发布”。
4. 在编辑器的预览链接或对应 GitHub 拉取请求中打开 Netlify Deploy Preview，检查桌面和手机布局、图片、灯箱与文案。

Deploy Preview 链接是不列出的随机地址，不需要登录即可打开；它不是私密链接，拿到 URL 的人仍可访问，因此不要在草稿中放入敏感信息。

## 检查与发布

1. Netlify 会在生成预览前清理新上传图片的 EXIF、IPTC、XMP、注释和时间元数据；`content-quality` 会重复验证并把需要清理的文件以 `Sanitize uploaded media` 提交写回同一草稿分支。
2. 自动检查同时验证内容结构、媒体引用、Jekyll 构建、桌面/手机布局和灯箱交互。
3. 只有 `content-quality` 和 Netlify Deploy Preview 均成功，且你已亲自查看预览后，才点击“发布”。发布会合并草稿到 `master`，然后由 GitHub Pages 更新正式站。

## 失败恢复

- 如果提示图片不支持，将文件转换为 `.jpg`/`.jpeg`、`.png` 或 `.webp` 后重新上传。
- 如果提示图片缺失，重新选择已上传的图片，并确认作品文件中的 `image` 路径以 `/assets/images/works/` 开头。
- 如果提示 `work_order` 重复，在“站点设置”的对应作品顺序中删除重复项；如果提示 `featured_work`，重新选择一件已经发布且当前可见的摄影作品作为首屏。
- 如果构建或测试失败，不要发布。打开 GitHub Actions 中失败的步骤，根据路径和字段提示修改草稿，保存后等待新检查。

## 回滚

1. 小改动优先在编辑器中建立一个新草稿，把字段或作品恢复为上一版，完成预览和检查后再发布。
2. 如果必须回退整个发布，在 GitHub 中对对应合并提交执行 Revert，通过新的拉取请求运行同样的检查，不要强制推送或改写 `master` 历史。

## 服务验证记录

Netlify 站点标识、实际的 Deploy Preview 状态名、分支保护规则和完整回滚验证将在首次托管配置后补充，不记录任何密钥或账号邀请信息。
